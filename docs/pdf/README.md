# نسخهٔ PDF مستندات

هر سند `.md` پروژه یک PDF فارسی و راست‌به‌چپ دارد. این فایل‌ها **تولیدشده** هستند؛
منبع، همان Markdown است.

| PDF | از فایل | محتوا |
|---|---|---|
| `README.pdf` | `README.md` | معرفی، ساختار، شروع سریع |
| `how-to-use.pdf` | `docs/how-to-use.md` | راهنمای استفاده قدم‌به‌قدم |
| `how-to-add-to-canoe.pdf` | `docs/how-to-add-to-canoe.md` | افزودن پنل/متغیرها به CANoe 12 |
| `docs-README.pdf` | `docs/README.md` | راهنمای کامل فنی |
| `canoe-README.pdf` | `canoe/README.md` | فایل‌های سمت CANoe |

## بازسازی

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r tools/requirements-pdf.txt

python tools/build_pdf.py            # همه
python tools/build_pdf.py --only how-to-use
python tools/check_pdf.py            # بررسی خودکار خروجی
```

`check_pdf.py` این‌ها را چک می‌کند و در صورت ایراد با کد خطا خارج می‌شود:
وجود همهٔ فایل‌ها، سالم بودن لایهٔ متن (نه تصویر)، نبود کاراکتر کنترلی جهت،
نبود گلیف گم‌شده، و اینکه متن دوبار شکل‌دهی نشده باشد.

> PDFها در گیت هستند تا نیازی به اجرای پایتون نداشته باشید. اگر سندی را
> ویرایش کردید، `build_pdf.py` را دوباره اجرا کنید و خروجی را commit کنید.

## چرا این‌طور ساخته شده

در این محیط pandoc، LaTeX، Chromium و WeasyPrint در دسترس نبودند (نه باینری،
نه کتابخانهٔ سیستمیِ Pango/Cairo). بنابراین Markdown به یک درخت بلوک ساده تبدیل
می‌شود و روی بوم A4 چیده می‌شود.

نکته‌های فارسی که واقعاً باید درست باشند و در `tools/build_pdf.py` حل شده‌اند:

1. **شکل‌دهی حروف** — با موتور خودِ fpdf2 (HarfBuzz). نسخهٔ اول گلیف‌ها را دستی
   می‌چید و همهٔ حروف روی هم می‌افتادند؛ آن روش کنار گذاشته شد.
2. **ترتیب دوجهته** — پاراگراف فارسی با `direction="rtl"` رندر می‌شود، پس
   `تب «اتصال» → گزینه HS-CAN` درست خوانده می‌شود.
3. **ایزوله‌ی توکن‌های فنی** — `#include` بدون ایزوله به‌صورت `include#` درمی‌آید.
   هر توکنی که با کاراکتر خنثی شروع شود (مثل `#include`، `/api/state`،
   `--take-control`، `DRIVE_MODE=1`) داخل `LRI…PDI` گذاشته می‌شود. توجه: باید
   فقط توکنی ایزوله شود که با کاراکتر خنثی شروع می‌شود؛ ایزوله‌کردن نصفهٔ یک
   مسیر (`tools/doctor.py` بدون `python`) بدتر از نبودش است.
4. **فونت مونواسپیس برای بلوک کد** — دیاگرام ASCII در `docs/README.md` فقط با
   فاصله‌های یکسان درست درمی‌آید.
5. **فونت جایگزین برای نمادها** — Vazirmatn فلش `→`، کشیدن کادر `│─` و `▶` را
   ندارد؛ DejaVu این‌ها را می‌دهد.
6. **ایموجی‌های رنگی** — `✅` و `❌` در هیچ فونت متنیِ معمول گلیف سیاه‌وسفید
   ندارند و در PDF به مربع خالی تبدیل می‌شوند، بنابراین در متن‌ها به `✓` و `✗`
   تبدیل شدند.
